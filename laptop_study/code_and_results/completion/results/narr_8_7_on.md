**8.15 The dead-network guard raised false alarms (a mistake found and fixed on 21 September).** The engine aborts a run when the predicted change map is identical across validation windows (per-pixel spread below 1e-5 m). It fired eight times: six original-model runs (UK 60 m and 30 m, epoch 2-5) and two side-channel runs (UK 60 m fold 1: the frozen seed at epoch 13 and a retry with the next seed at epoch 6). Seven of the eight were verified as **false alarms** by finishing them with the guard disabled and the same seed: the six original-model runs trained normally (+0.18 to +0.195) and the frozen-seed side-channel run scored +0.885; the eighth (the retry) was not re-run. Cause: the check used the 12 EARLIEST held-out windows (code review finding F13), in which the flood has barely started, so even a healthy network predicts nearly no change; slow-starting models (the original) look "dead" for the first epochs. Fix (21 September, 00:00): the check now samples 12 windows spread over the whole held-out period; it only changes the decision to abort, never the training, and every run that passed the old check is valid. I first described the aborts as "collapses" in messages during the day; that was wrong and is corrected here and in the report table "Runs aborted by the dead-network guard".
